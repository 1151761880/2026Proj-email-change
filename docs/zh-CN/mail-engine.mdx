## 1. 模块职责

`mail-core` 定义邮箱数据、查询、操作状态和引擎接口，不依赖 React、DOM、Next.js、Electron 或具体数据库驱动。网页与桌面宿主提供各自适配器。

| 模块 | 职责 |
| --- | --- |
| `mail-core` | 状态与操作语义、查询和引擎接口 |
| `mail-sqlite` | 数据结构、参数化查询和事务存储 |
| `mail-react` | React 对共享状态的订阅接口 |
| `mail-ui` | 网页和桌面共享的 React DOM 展示 |
| `email-editor` | 邮件 HTML 交换与编辑 |

## 2. 宿主提供的能力

引擎由 `MailStore`、`MailboxSource`、`OperationExecutor` 和 `HostRuntime` 等能力构造。宿主负责存储连接、认证、传输、时间、标识生成和运行生命周期。

页面观察邮箱、会话和操作状态，不另行维护一套独立的邮件事实。

## 3. 主要接口

| 接口 | 用途 |
| --- | --- |
| `observeMailbox`、`observeMailboxWindow` | 观察邮箱视图和窗口 |
| `observeConversation` | 观察会话 |
| `observeOperation` | 观察操作状态 |
| `saveDraft`、`readDraft` | 保存与读取草稿 |
| `submitSend` | 提交发送操作 |

账户列表、Outlook 文件夹和 Gmail 标签仍走对应应用 API。附件保存在服务商的邮箱草稿中，引擎不持有其字节内容。

## 4. 状态与一致性

客户端查询以有效邮件状态为准；待执行操作及其显示效果需要一致保存。同步进度与已接受的数据变化要共同处理，避免恢复后误跳过变化。

准备中的会话操作与可执行操作应分别显示。服务商结果未知的操作不能简单当成确定失败并直接重发。

## 5. SQLite 存储

共享驱动合同包括事务、回滚、串行写入、保存点、二进制数据和关闭重开等能力。邮件正文使用带格式标记的压缩 BLOB，搜索索引及 FTS5 能力按宿主可用性处理。

这层负责客户端邮件数据，不取代后端 Prisma/PostgreSQL 业务库。具体版本要求和性能检查入口见各 `mail-*` 包的 README。

## 6. 设计资料

`docs/plans/mail-engine-plan.md` 保留架构演进与历史方案，其中附件暂存等部分已被后续设计替换。当前实现以包接口、调用方和测试为依据，历史方案只用于追溯。
