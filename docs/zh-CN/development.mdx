## 1. 环境与工作区

使用 Node.js 24 和根目录指定版本的 pnpm。网页应用位于 `apps/web`，共享库位于 `packages`，桌面应用位于 `apps/desktop`。

先安装依赖：

```sh
pnpm install
```

本地演示使用 `pnpm local:start`。使用自己的数据库、邮箱和模型配置进行常规开发时，按环境准备后使用 `pnpm dev`。

## 2. 代码入口

| 内容 | 路径 |
| --- | --- |
| 页面与路由 | `apps/web/app/` |
| 共享页面组件 | `apps/web/components/` |
| 服务端变更操作 | `apps/web/utils/actions/` |
| 业务和服务商适配 | `apps/web/utils/` |
| 数据结构与迁移 | `apps/web/prisma/` |
| 集成、浏览器及模型测试 | `apps/web/__tests__/` |
| 桌面宿主 | `apps/desktop/src/` |
| 可复用邮件代码 | `packages/mail-*/`、`packages/email-editor/` |

## 3. 开发边界

页面、共享引擎、存储适配器和邮箱服务商各有职责。已有共享模块优先复用；功能专属逻辑放在所属模块，跨功能的基础设施保持通用。

邮件服务商调用优先通过已有 `EmailProvider` 抽象。需要区分 Google 与 Microsoft 的地方集中在真实适配边界。请求校验沿用 Zod，网页数据获取和变更沿用项目已有 SWR、服务端操作及表单模式。

## 4. 常用命令

| 命令 | 用途 |
| --- | --- |
| `pnpm local:start` | 启动隔离的本地演示环境 |
| `pnpm dev` | 启动常规网页开发服务 |
| `pnpm desktop` | 启动桌面客户端开发入口 |
| `pnpm check` | Biome/Ultracite 检查 |
| `pnpm fix` | 按既有配置修正文档支持的格式及代码问题 |
| `pnpm test <测试文件>` | 针对性的网页单元测试 |
| `pnpm test:packages` | 共享包测试 |
| `pnpm build` | 需要时构建网页应用 |

先选择能覆盖实际改动的检查。修订文档通常检查格式、引用和命令即可；不需要为证明工作量启动整个应用或重复运行无关测试。

## 5. 文案与测试维护

界面按钮和标签改名会影响按可见文字定位的浏览器测试，修改时查找并同步相关定位器。测试结果只说明实际执行的范围，跳过或未配置的场景应明确记录。

## 6. 开发工具配置

专用 AI 规则和编辑器工作区配置已从本仓库移除。Next.js 在检测到 AI 开发环境时，可能自动生成应用目录中的 `AGENTS.md`、`CLAUDE.md` 提示文件；这属于框架行为，不是邮件业务依赖。

维护中文文档时，直接修改相应页面，并检查 `docs/docs.json` 导航和 `docs/README.md` 索引。
