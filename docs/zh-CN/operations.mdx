## 1. 本地运行数据

`.context/local-dev/` 保存隔离数据库、启动凭据和当前服务地址；`.context/native/` 保存便携程序。关闭终端后再次启动，数据库会保留，部分缓存和模拟服务会重新初始化。

不要仅为清理目录删除数据库。PostgreSQL 主版本升级前应备份并采用对应迁移方式，同一数据目录不能直接由不匹配的主版本打开。

## 2. 备份范围

| 内容 | 处理要点 |
| --- | --- |
| PostgreSQL | 保存业务数据与迁移状态，核对恢复结果 |
| 配置与加密材料 | 受保护地保存，恢复邮箱凭据时需要相匹配的材料 |
| 镜像及源码版本 | 保存可复现的版本标识和部署参数 |
| Redis/队列 | 区分可再生缓存与需要恢复的任务状态 |
| 客户端数据库 | 按实际宿主和恢复需求保存 |

运行中的数据库优先采用数据库工具生成备份。直接复制正在写入的数据目录不能保证一致性。

## 3. 数据库备份示例

下面使用 POSIX 命令行；连接地址由运行环境提供，备份与恢复分别指向正确数据库：

```sh
pg_dump --format=custom --file=projectemail.dump "$DATABASE_URL"
pg_restore --dbname="$RESTORE_DATABASE_URL" --no-owner --no-acl projectemail.dump
```

先在单独的测试数据库恢复，再检查账户、规则、关键记录和应用读写。恢复命令会写入目标库，目标地址须在执行前核对。

## 4. 更新与回滚

固定镜像或源码版本，升级前保存数据库备份和原配置。应用数据库迁移后，回滚镜像不会自动回滚数据库结构。根据迁移兼容性选择恢复数据库或继续修复。

中文文档的原文备份只保存文档资源，不包含业务数据库或运行密钥。

## 5. 密钥与授权维护

区别处理模型密钥、OAuth 凭据、内部认证和邮箱加密材料。更换邮箱加密材料前，确认已有密文的读取及迁移方式，避免导致账户必须重新连接。

授权过期、被撤销或服务商订阅异常时，从账户设置重新连接，并核对后续邮件同步。

## 6. 运行观察

关注应用和 worker 状态、数据库/Redis 连通性、失败任务、调度调用、Webhook、邮件通知和模型请求。发现错误时记录发生时间、对应组件和具体错误，优先排查该调用链。

不要将完整邮件正文、附件内容或密钥放入常规日志。账户操作结果应结合应用记录和服务商状态判断。
