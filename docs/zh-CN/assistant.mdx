## 1. 智能助手的用途

从侧栏“智能助手”进入。聊天用于当前查询和交互，自动化规则用于按已保存条件处理邮件。可用中文描述任务，无需沿用原文中的英语指令。

例如：“找出本周尚未回复的客户邮件”“给这封邮件起草一份简短回复”“把收据标记为财务资料”。处理真实邮箱时，结果和实际操作会受当前账户权限及启用工具影响。

## 2. 聊天功能

助手可搜索邮件、阅读会话、解释处理结果、准备邮件内容、维护规则，并在已连接日历时查询安排。发送邮件按应用提供的确认卡片操作。

聊天可使用图片和受支持的邮件附件内容作为上下文。聊天上传与邮件发送附件是两个入口。历史会话可重新打开、重命名或删除。

## 3. 创建规则

1. 在智能助手的规则界面输入处理要求，或打开手动添加规则入口。
2. 核对生成的匹配条件和各项操作。
3. 保存规则，在测试界面检查样例或近期邮件的匹配结果。
4. 启用后，从处理历史查看实际匹配和操作记录。

规则由条件及一个或多个操作组成。条件可包含语义要求，也可匹配发件人、收件人、主题等字段。可用操作包括标签、类别、移动文件夹、归档、草稿、回复、转发、已读、星标、摘要、Webhook 和已连接服务的相关操作。

## 4. 内容生成与延迟操作

可编辑内容中的双花括号表示根据邮件上下文生成的部分：

```text
您好，{{姓名}}：
{{用简短的中文确认已收到资料，并询问预计完成时间}}
谢谢。
```

花括号以外的文字按原样保留。对支持延迟的操作，在操作选项中添加延迟；已有范围为 1 分钟至 90 天。延迟属于具体操作，同一规则的其他操作可以另行设置。

## 5. 会话、多规则与学习记录

“应用于会话”关闭时，规则只处理会话中的首封邮件，后续回复跳过。默认每封邮件选择一条规则；需要多条规则匹配时，在设置中开启多规则选择。

可在规则中查看发件人和域名等学习记录。发现错误匹配时，从历史结果纠正，并检查是否存在不适用的学习记录。

## 6. 测试与实际执行

“测试全部”用于评估邮件与规则的匹配，不直接执行全部规则操作。保存、启用后的规则按其操作定义执行；回复、转发等操作与仅生成草稿的效果不同，应逐项核对。

本地演示的预设模型响应主要用于流程检查。真实模型效果需要在相应配置下单独验证，方法见[测试说明](/zh-CN/testing)。
