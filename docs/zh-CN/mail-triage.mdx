## 1. 功能范围

侧栏“邮件整理”对应 `/<emailAccountId>/mail-triage`。每个账户有一个独立模拟邮箱，首次包含 M01—M12 共 12 封虚构邮件。样本、建议和归档日志保存到数据库，刷新页面后保留。

本功能不归档已连接的真实 Gmail/Outlook 邮件，也不运行其他自动化规则。

## 2. 模型配置

在 `apps/web/.env.local` 中填写：

```dotenv
MAIL_TRIAGE_API_KEY=填写自己的模型密钥
MAIL_TRIAGE_BASE_URL=https://api.deepseek.com
MAIL_TRIAGE_MODEL=deepseek-flash
```

以上模型标识沿用当前功能配置；实际调用时应确认服务端可用。配置只保存在服务端，三个变量由本地启动器额外加载，与常规助手模型配置相互独立。

页面可调用真实模型分析虚构邮件，使用 JSON 输出并核对类别、邮件 ID 和逐字引用。浏览器自动化测试明确使用本地模型模拟器。

## 3. 数据库准备

首次使用或结构更新后，安装依赖并为目标开发数据库生成客户端及应用迁移：

```sh
pnpm install
pnpm -F inbox-zero-ai exec prisma generate
pnpm -F inbox-zero-ai prisma:migrate:local
```

自动启动流程会处理其隔离环境的准备；手动迁移命令须指向你要维护的数据库。

## 4. 操作步骤

1. 点击“生成整理建议”，逐封查看类别、原文引用和解释。所有归档项初始不勾选。
2. 核对允许选择的候选邮件，再勾选需要归档的项。
3. 点击“确认归档”，核对邮件 ID，点击“执行归档”。
4. 在全部邮件和操作日志中核对结果。归档后邮件仍保留。

只有类别为“仅知悉”或“营销”、未星标、仍在收件箱且引用有效的邮件允许归档。待处理、不确定和星标邮件不可勾选。

## 5. 建议失效与重试

星标变化会使旧建议失效，需要重新生成。后台再次核对建议、邮件状态和邮箱版本；同一确认请求重复提交不会重复记录操作。

分析请求超时为 15 秒，页面等待 20 秒后显示错误。失败会清空旧建议和选择，保留邮件及日志，之后可点击“重试”。

## 6. 样本与验收工具

验收工具可重置 12 封样本、模拟 HTTP 503 或超时，以及导入合成邮件 JSON。重置和导入会清除该模拟邮箱的旧建议与日志。

导入格式为数组，每项包含 `id`、`from`、`subject`、`body`、`starred`、`inbox`；ID 须唯一，每批最多 50 封。导入内容会在分析时发送到配置的模型服务。

固定样本为 `apps/web/public/fixtures/mail-triage.csv`。预期分类只保存于测试真值，不发送给模型。专项测试命令和结果边界见[测试说明](/zh-CN/testing)。
