## 1. 部署组成

真实服务需要网页应用、PostgreSQL、Redis/HTTP 接口、邮箱授权、模型配置，以及启用功能所需的队列、定时任务和通知服务。对外回调通常需要可访问的 HTTPS 地址。

本地演示的启动方法见[快速开始](/zh-CN/quick-start)。以下面向使用真实邮箱的部署。

## 2. 准备配置

复制 `apps/web/.env.example` 为 `apps/web/.env`，在编辑器中填写自己的配置，重点核对：

1. 对外地址与数据库、Redis 连接。
2. 会话密钥、邮箱凭据加密材料和内部服务认证。
3. Google 或 Microsoft 授权凭据。
4. 模型角色及模型服务密钥。
5. 所选任务队列、定时任务与邮件通知服务。

具体字段见[配置说明](/zh-CN/configuration)。Docker 网络中的数据库、Redis 主机名与宿主机的 `localhost` 不同，配置须与实际网络一致。

## 3. 运行定制版镜像

本仓库提供本地镜像脚本：

```sh
pnpm install
pnpm docker:local:build
pnpm docker:local:run
```

这组脚本使用 `docker/` 中的构建及运行资源，适用于具备脚本所需工具的环境。镜像仓库、标签及应用配置以脚本和 Compose 文件为准。

自行编排时，使用当前源码构建的镜像，并将相应服务的 `image` 指向该镜像。原有部署文件中可能默认使用上游镜像；仅修改本地源码不会改变已拉取镜像的内容。

根目录 `docker-compose.local.yml` 用于演示启动器的数据库/缓存；`docker/docker-compose.local.yml` 用于配套运行本地构建镜像；根目录 `docker-compose.yml` 提供完整服务编排参考。

## 4. 数据库与后台任务

将数据库迁移应用到选定数据库，并确认前端和后台进程使用相同的配置。启用 BullMQ 时要运行消费进程；选择其他队列后端时，按对应方式部署。

定时任务需要调度器及 `CRON_SECRET`。Web 进程可响应任务请求，但启动网页不代表所有后台任务已经调度。具体说明见[消息推送与后台任务](/zh-CN/jobs-and-webhooks)。

## 5. 初次连通检查

登录后核对邮箱授权状态、邮件同步、模型请求和已启用任务。需要检查真实收发时，用自己的受控邮箱完成对应操作，并核对服务商侧结果。

本页给出部署方法，不记录本次真实服务的部署结果。生产维护、升级与恢复见[运行维护](/zh-CN/operations)。
